GACEE · Architecture

数字基础设施与协会 AI 服务平台 · 架构方案Digital Infrastructure & Association AI Platform — Architecture Blueprint

本方案覆盖 GACEE 官网、协会 AI 服务平台（hub.gacee.org）、内部 IM 协作（Mattermost）、系统邮件与平台 AI 的整体架构、选型、部署、成本与实施路线。基础设施与 Juris&Edu 同处阿里云新加坡，以复用换经济、以隔离保产权。

00决策摘要

四项关键取向已确认，架构围绕其展开：

部署形态复用 JE 阿里云集群

现有新加坡 ACK 加 1 个专属节点 + 独立 namespace / 数据库；共享底层，隔离数据与产权。

IM 协作Mattermost 开源自托管

仅内部团队（≤50 人），im.gacee.org，零许可费、数据自持。

系统邮件DirectMail + Alimail

事务邮件走阿里云邮件推送（子域发信）；人对人邮箱保留 Alimail 免费版。

平台 AI独立 JE Agent · 首期即上

用 JE 代码单独部署一套实例，内容 AI 初审 + 基础项目编排。

01目标与边界

要打通的五件事

  • 内容中枢：平台作官网 headless CMS，投稿→AI 初审→人工复核→发布→官网实时拉取。
  • 协作打通：内部团队 IM（Mattermost）与平台身份、通知贯通。
  • 统一身份：平台为身份中心，一套账号登录平台与 IM。
  • 统一邮件：验证码 / 通知 / IM 提醒统一走 DirectMail，送达可靠。
  • 平台 AI：独立 JE Agent 承载内容初审与项目模版化编排。

明确的边界

  • 与 JE 解耦：仅共享底层基础设施，应用与数据独立（不做 JE 租户）。
  • 与山海同文分开：learn.gacee.org 独立系统，仅经接口衔接（如统一发证）。
  • 产权归协会：数据、账户、收款均在协会名下，驻留新加坡。
  • 不纳入：留学招生托管不进本平台。

04部署与隔离

复用而隔离

  • JE 现有 ACK 加 1 个专属工作节点承载 gacee 三个工作负载（集群此前已"单节点满"，不硬塞）。
  • 独立 namespace: gacee + NetworkPolicy 限制跨 ns 流量。
  • RDS 同实例、独立 database + 独立账号（platform / mattermost / agent），禁跨库外键。
  • Redis 独立 db-index / key 前缀；OSS 独立 bucket。
  • 机密走 K8s Secret（复用 JE KMS 模式；注意生产 APP_ENV 留空的既定约定）。

入口与发布

  • Ingress hosts：hub（平台）·im（Mattermost）·ai（Agent，可仅内网）·verify（发证验真，二期）。
  • TLS：cert-manager + Let's Encrypt 自动签发。
  • 镜像：sha 不可变镜像 + canary/GA 门禁（复用 JE 发布纪律）。
  • Payload 自托管：standalone Next 输出 + 外部 PG 连接池 + 媒体走 OSS adapter；vercel.json 仅留给官网。

05身份与统一登录

平台（gacee-platform）为身份中心：会员、角色与认证态集中于此（10 角色 × 认证 × 可见性 RBAC 已在骨架 rbac.ts）。登录 = 邮箱 + 密码 + 邮箱验证码（验证码经 DirectMail 下发）。

Mattermost SSO 的现实约束：开源 Team Edition 仅内建 GitLab OAuth2 一种第三方登录。打通路径：平台对外暴露一组 GitLab 兼容的 OAuth2 端点（authorize / token / user），Mattermost 指向它即可一套账号登录。首期内部 ≤50 人也可先用 Mattermost 本地账号 + DirectMail 邀请，SSO 作为紧接增强；未来平台升级为标准 OIDC IdP，供更多系统统一登录（阶段 2）。

06邮件架构

系统事务 · DirectMail

  • 专用发信子域 mail.gacee.org，避开主域 Alimail 的收信 MX。
  • Vercel DNS 配 DirectMail 的 SPF / DKIM / MX(退信) / CNAME 校验。
  • 统一发信服务：平台 mailer、Mattermost SMTP、Agent 通知都指向 DirectMail 新加坡节点 smtpdm-ap-southeast-1.aliyuncs.com:465。
  • 用途：注册验证码、审批/对接通知、IM 提醒、结算回执。

人对人 · Alimail（保留）

  • postmaster + 12 个成员邮箱不变；info@ 收官网联络。
  • 免费版个人 SMTP 不承担系统群发（频率上限 / 送达风险）。
  • 主域 DMARC 现 p=none；子域发信对齐后逐步收紧至 quarantine。

07平台 AI（独立 JE Agent）

用 jurisedu 的 Agent 代码构建独立镜像，部署于 ns gacee，配独立数据库与配置，不依赖 JE 任何在线服务——即"同源代码、独立部署，数据与运行时隔离"。

首期能力

  • 内容投稿 AI 初审：合规敏感筛查 / 润色纠错 / 事实标注 / 分类打标摘要，接入 Payload 投稿工作流（投稿→AI 初审→人工复核→发布→官网拉取）。
  • 基础项目模版化编排：研学等项目一键生成多语招生文案与素材草稿 → 人审。

二期深化

  • AI 宣传视频、社媒素材成套生成。
  • 报名+收费+触达全流程编排，数据回流。
  • TIDAR KAG 低幻觉问答（资源/项目知识库）。

09实施路线图

Phase 0 · 基础设施打底~1 周

Terraform 扩展：+节点、namespace、3 库+账号、OSS bucket、DirectMail 发信域与 DNS；容器化 gacee-platform（Dockerfile + Payload 自托管适配 + OSS adapter）；CI/CD（sha 镜像，复用 JE Actions）；ingress hosts + 证书。

Phase 1 · 平台 MVP 上线~2–3 周

Payload 内容中枢（投稿/审核/发布）+ 官网 headless 对接（gacee-site 改拉平台内容 API，ISR）+ 会员注册登录（邮箱+密码+验证码 via DirectMail）+ 核心 RBAC，hub.gacee.org 上线。

Phase 2 · IM 打通~1–2 周

Mattermost 部署 im.gacee.org + DirectMail 通知 + 内部团队/频道结构（秘书处/运营/技术/项目组）+ SSO（GitLab 兼容 OAuth 接平台）。

Phase 3 · AI 服务首发~2–3 周

独立 JE Agent 部署 + 内容 AI 初审接入投稿流水线 + 基础项目模版化编排（1 个研学项目模板试点）。

Phase 4+ · 业务模块迭代持续

研学地图（Mapbox 报名/缴费）、统一发证验真（verify.gacee.org）、商业 BI、供应链/财务/资产中枢——按《协会平台规划纲要》推进。

10安全 · 合规 · 运维

安全与合规

  • 数据驻留全部阿里云新加坡，与 JE 一致；产权在协会名下。
  • 隔离：独立库/账号/namespace/NetworkPolicy；接口而非直连 JE。
  • 全站 HTTPS（cert-manager + LE）；机密 K8s Secret + KMS 模式。
  • 跨云 API（官网↔平台）：CORS 白名单 gacee.org + ISR 缓存 + 失败降级。

备份与运维

  • RDS 自动备份（PITR）；Mattermost 库每日逻辑备份 → OSS；OSS 版本+生命周期。
  • 季度恢复演练。
  • 监控复用 JE observability（指标/日志/告警）；成本纳入 cost-control。
  • 发布 sha 不可变镜像 + canary/GA；单节点承载期后端发布 maxSurge:0。

11关键风险与对策

基础设施

  • JE 集群"单节点满" → 必须加专属节点，禁硬塞；gacee 负载设 requests/limits + 亲和隔离。
  • Payload 3 自托管（非 Vercel）→ standalone + 外部 PG 连接池 + OSS 媒体；vercel.json 仅官网用。

集成

  • Mattermost 开源 SSO 仅 GitLab → 平台出 GitLab 兼容 OAuth；或首期本地账号，SSO 紧随。
  • DirectMail 与 Alimail 域冲突 → 发信用子域 mail.gacee.org，收信 MX 留主域；SPF/DKIM 分域对齐。
  • 跨云 CORS/缓存 → 平台内容 API 经 ingress 公网可达 + 白名单 + ISR + 快照降级。

12决策记录 ADR

ADR-G1 · 复用 JE ACK + 数据隔离（而非独立集群或单机）——经济与专业兼顾，产权边界清晰。
ADR-G2 · Mattermost Team Edition 自托管——零许可、数据自持，内部规模足够。
ADR-G3 · DirectMail 子域发信 + Alimail 人用——送达率与省钱兼顾，互不干扰。
ADR-G4 · 独立 JE Agent 同源部署——AI 能力复用 + 数据/运行时隔离。
ADR-G5 · 平台为身份中心，Mattermost 经 OAuth 接入——统一登录路径。

13下一步

建议从 Phase 0 起步：先把 gacee-platform 容器化并接通阿里云新加坡（节点/命名空间/数据库/OSS/DirectMail 域名），跑通 hub.gacee.org 的空壳部署与 CI/CD，再进入 Phase 1 的内容中枢与会员登录。每阶段以可上线、可回滚为门禁。
